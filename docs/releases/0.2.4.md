# Phoenix BYOC 0.2.4

Application update from 0.2.3, frozen from Preview on 2026-10-28. Web, frontend,
Engine and Agents are updated; Gateway and infrastructure images are unchanged.

## Changes

- Web includes dashboard/timezone, review, toast and workflow-dialog fixes.
  Eval launch forwards the application's execution placement.
- Engine adds pool configuration and VM provisioning APIs, detects lost sandbox
  executions, respects SDLC placement for evals, and skips unused Cortex inputs.
- Evals have five workers per lane by default. The saved-input migration adds
  the required Gateway eval permissions without rotating existing credentials.
- Engine chart 0.2.7 exposes the sandbox resource catalog while BYOC retains
  the customer's configured resource classes. Frontend chart 0.1.1 increases
  upload limits. Existing immutable chart versions are not overwritten.

## Agent and pool configuration

The new Agent provides chat attachment delivery, pool setup-script execution,
pool-secret diagnostic redaction, checkpoint restoration improvements and
publication fixes. Existing workflows retain their pinned images and bundles;
start new workflows for the new Agent features. Custom pool image overrides
must also use a compatible Agent version.

`secrets.application.devBoxSecretsKey` is generated once by the installer. It is
a base64-encoded 32-byte AES-256 key for pool secret variables. Existing passwords
and tokens are preserved. Keep this key for future upgrades and recovery; an
empty key disables pool secret variables. Invalid nonempty keys fail rendering.

## Upgrade and validation

Engine adds pool configuration columns and environment-variable/run-configuration
tables. Migrations run during installation; there is no data-service replacement.
Web has no new migration files relative to 0.2.3. Preserve existing values,
secrets, GCP VM settings and Workload Identity bindings. Run the saved eval
configuration migration described in [the upgrade procedure](../../UPGRADE.md).

Application CI passed, including the new Agent's final-image runtime smoke.
Its [Preview deployment](https://github.com/canonix-engineering/phoenix-devops/actions/runs/40757946774)
passed. All nine Preview Deployments were ready and matched the frozen release
images, and the Engine selected the exact Agent digest.

The existing AWS EKS `phoenix-byoc` installation, previously on 0.2.2, was
upgraded to the final candidate with these exact application images and charts.
The installer and `verify.sh` passed. Existing record counts, PVC identities and
credentials were preserved; the intended eval scopes were added. The new pool
key was generated in the existing secrets file and matched the live Engine
Secret. All nine Deployments were available.

One existing smoke workflow ran successfully with the final Agent: it executed
a Web-published bundle and returned the expected report through the Artifact
API, including non-root/FUSE evidence. The original Engine catalog and Helm
values were restored exactly afterward. This is a basic execution check, not
end-to-end acceptance of every new UI feature.

All 65 rendered Kubernetes resources passed schema validation. The 46 existing
repository tests passed, and pool-key rendering and malformed-key rejection
were checked. Customer read-only ECR credentials could read all five updated
image manifests and obtain their layer download URLs. Both new public charts
were downloaded anonymously and their checksums verified. No application
images were rebuilt or repackaged for this release.

No customer GCP deployment or test was performed. Sandbox scale-from-zero,
suspension/resume and the complete chat-attachment/pool-configuration UI flows
were not separately revalidated in this rehearsal.
