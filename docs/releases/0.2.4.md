# Phoenix BYOC 0.2.4 — release preparation

Status: development candidate, not published or approved for customer use.
Agents promotion to Preview is pending; the final Agent pin, related configuration
and feature availability must be updated before this release is published.

Web, frontend and Engine update from Preview on 2026-10-28. Agents temporarily
remain at the exact 0.2.3 image for preliminary validation; Gateway and
infrastructure images are unchanged.

## Changes

- Web includes dashboard/timezone, review, toast and workflow-dialog fixes.
  Eval launch forwards the application's execution placement.
- Engine adds pool configuration and VM provisioning APIs, detects lost sandbox
  executions, respects SDLC placement for evals, and skips unused Cortex inputs.
- Evals have five workers per lane by default. The saved-input migration adds
  the required Gateway eval permissions without rotating existing credentials.
- Engine chart 0.2.7 exposes the sandbox resource catalog while BYOC retains
  the customer's configured resource classes. Frontend chart 0.1.1 increases
  upload limits. Existing immutable chart versions are not overwritten.

## Agents promotion pending

Agents PR #432 has merged into Preview at
`f28a6a5f455a6804c0b2e2ac53a912c62a6b7b99`; its image CI and Preview rollout
must complete before the release manifest is updated. The current temporary
pin is still the 0.2.3 image. Do not deploy this preparation branch to customers.

The new Agent provides chat attachment delivery, pool setup-script execution,
pool-secret diagnostic redaction, checkpoint restoration improvements and
publication fixes. These require the new image and must not be claimed as
qualified while the temporary pin remains.

The BYOC configuration now prepares `secrets.application.devBoxSecretsKey` for
automatic one-time generation. It is an AES-256 key for pool secret variables;
existing passwords and tokens are preserved. Keep this key for future upgrades.
Do not enable pool secrets with the temporary old Agent image.

## Upgrade and validation

Engine adds pool configuration columns and environment-variable/run-configuration
tables. Migrations run during installation; there is no data-service replacement.
Web has no new migration files relative to 0.2.3. Preserve existing values,
secrets, GCP VM settings and Workload Identity bindings.

Preliminary upgrade from 0.2.2 in AWS EKS `phoenix-byoc` passed the installer
and `verify.sh` with the temporary Agent pin. All nine Deployments were ready;
existing record counts, PVC identities and credentials were preserved. The only
existing authorization change was the intended addition of eval scopes.
All 65 rendered Kubernetes resources passed schema validation. Repository tests
and validation of the new encryption-key rendering passed. Customer read-only
ECR access was checked for the currently pinned images; both new charts were
also downloaded anonymously and their checksums verified.

Final qualification is pending the new Agent image and Preview rollout. A
workflow execution with the final images has not yet been checked. No customer
GCP deployment or test was performed. See [the draft upgrade procedure](../../UPGRADE.md).
