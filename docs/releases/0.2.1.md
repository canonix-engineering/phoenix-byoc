# Phoenix BYOC 0.2.1

Installer correction for the existing CSG PoC. Application images and chart
versions are identical to [0.2.0](0.2.0.md). No image builds or new credentials
are required. Use tag `v0.2.1` and follow [UPGRADE.md](../../UPGRADE.md).

- Adds explicit `install.sh --discard-redis-state` for a small PoC that can
  discard old Redis-held state and start workflows on a fresh Valkey volume.
- Preserves the original Redis PVC and the `redis-client` endpoint, pauses
  application Deployments during cutover and restores their replica counts.
- Keeps the normal migration guard when the option is omitted. Repeating the
  option does not clear an existing Valkey instance.
- Adds failure/retry checks and self-service instructions with optional backups.

The shortcut does not copy Redis queues, streams or other Redis-held state.
Finish workflows and pause user activity before updating. PostgreSQL records
and artifact files are not deleted by the cache cutover.

## Validation

The Redis 8.8.0 → pinned Valkey 9.1.2 cutover was exercised in an isolated local
Kubernetes namespace using the published Redis chart 1.6.18 and two test clients.
Both clients resumed; the original Redis PVC identity/binding and compatibility
Service identity/IP were preserved. A repeat run retained a Valkey test key.
The static BYOC suite and automated cutover failure/retry tests passed.

This is a cache cutover rehearsal, not a full GCP installation test. The unchanged
application release was qualified on the EKS simulator as recorded for 0.2.0;
the customer's GCP workflow remains part of post-upgrade acceptance.
