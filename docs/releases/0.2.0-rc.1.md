## Changes since the previous BYOC application baseline

- Web: workflow progress and Brief presentation, artifact names and visibility,
  human questions and answer context, pull-request links/diffs and GitHub feedback,
  evaluation results and app overview/workflow views, ActionCable recovery, and
  database migrations/rematerialization without demo data seeding.
- Gateway: engine-signed toolbox capabilities, integration and GitHub/SSH relay
  fixes, bounded provider requests, and scoped public agent routes. Capability
  verification stays in `observe`; this release does not enable `enforce`.
- Engine: standalone immutable artifact publication/lookup, scoped read grants,
  durable retry/resume state, external pool provisioning and installation checks,
  evaluation evidence/admission, streaming artifact transfers, sandbox metrics,
  and per-attempt toolbox capabilities.
- Agent: durable workflow outputs and checkpoint/history handling, clearer human
  review gates, published artifact names, pull-request audit evidence and ticket
  links, toolbox capability propagation, and the unified output contract.
- Bundled PostgreSQL and Valkey remain part of BYOC. Customer GCP configuration,
  tenant, storage, domain, registry access and resource classes must be retained.

## Customer upgrade requirements

Follow [the upgrade procedure](../upgrades.md) and the
[customer upgrade instructions](../../UPGRADE.md). Reuse both existing values files,
back up PostgreSQL and persistent volumes, then use `install.sh --generate-secrets`.
It preserves current service credentials and adds the separate publisher token.
Web publication remains disabled unless explicitly needed.

Custom agent bundles require review before rollout: output definitions must use
`output_schema_relpath`; obsolete output/status schema fields are not compatible.
Do not copy supplier Preview/Test secrets, resource limits or node placement.

The shared `PHOENIX_WORKFLOW_ENGINE_TOKEN` must be nonempty, non-placeholder and
identical for Web, Gateway and Engine. This is distinct from the new optional
artifact publisher token. No token rotation is required when the existing value
already satisfies this condition.

After upgrade, verify existing-user login, an existing app, workflow execution,
artifact download, human answer/resume, worker activity and the customer's GCP
workflow. Helm rollback alone does not reverse database migrations.
