# Phoenix BYOC 0.2.0

Stable release qualified on 2026-10-20. Use tag `v0.2.0` and the attached
`phoenix-byoc-0.2.0.tar.gz` installation distribution. Follow
[UPGRADE.md](../../UPGRADE.md) for an existing installation; retain its values,
secrets, bundled databases and GCP configuration.

## Included changes

- Web: workflow progress and Brief presentation, artifact names/visibility,
  human questions, GitHub feedback and pull-request views, evaluation views,
  ActionCable recovery, migrations and application rematerialization.
- Gateway: per-attempt toolbox capabilities, integration/GitHub/SSH relay fixes
  and scoped public agent routes. Capability verification stays in `observe`.
- Engine: immutable artifact publication and lookup, scoped read grants,
  durable retry/resume state, external pool provisioning checks, streaming
  artifacts, admission/evaluation evidence and sandbox metrics.
- Agent: durable outputs, checkpoint/history handling, human-review flow,
  artifact names, pull-request evidence, capability propagation and the
  unified output contract.
- BYOC: required settings and Secret wiring, distinct publisher token,
  digest-pinned deployment/runtime image references, explicit migrations
  without demo seeding and deployed configuration verification.

Required new values, token handling and custom-bundle compatibility are listed
in [the upgrade procedure](../../UPGRADE.md#4-merge-the-required-values).

## Chart versions

Gateway `0.5.0`, Web `0.2.3`, Workflow Engine `0.2.5` and OpenSandbox controller
`0.2.3` were published through the normal chart workflow. Cortex `0.1.0` and
Frontend `0.1.0` remain unchanged. The installer includes its local helper
charts; `chart-index.json` inventories all remote and included charts.

## Qualification and access

- The existing `phoenix-byoc` simulator upgraded using published OCI charts and
  these exact application digests; `verify.sh` passed.
- Web login, API/ActionCable, worker activity, artifact upload/lookup/download
  and Agent draft → revision → approval → verification passed.
- Repeated installation preserved seven original PVC identities/bindings,
  existing secrets and a byte-identical artifact; all ten enabled Helm releases
  were deployed and the built-in workflow catalog was restored.
- The full BYOC static suite, rendered schema checks and compliance unit tests
  passed during candidate qualification.
- All twelve release image tags/digests and Linux amd64 manifests were readable
  using the existing customer read-only credentials; ECR layer-download
  authorization was confirmed. All nine external chart packages were
  downloadable without private registry credentials.

The customer keeps the existing direct-ECR configuration. No new credentials or
image builds are required. GCP VM lifecycle and a dedicated controller upgrade
were not exercised by the shared-controller EKS rehearsal; the customer's GCP
workflow is part of post-upgrade acceptance.

## Distribution scope

This is the installation distribution and its version/checksum inventory.
The six new application images have verified signed SBOM and corresponding-source
attestations. Retained infrastructure images keep their existing digests and
historical evidence. The all-images compliance packager still rejects missing
historical attestations; this installation archive does not claim to be that
complete compliance bundle, and no compliance enforcement is changed.
