# Phoenix BYOC 0.2.5

Application update from 0.2.4, frozen from Preview on 2026-10-30. Web, frontend,
Engine, OpenSandbox, Gateway and Agents use existing CI-built Preview images.
Infrastructure images and published OCI chart versions are unchanged. The local
PostgreSQL bootstrap chart advances to 0.1.2.

## Changes

- Workflow definitions can be published per application and are stored in the
  Engine database. New runs pin the visible definition catalog; descendants use
  that same catalog. Existing workflow history and pinned content are retained.
- Web adds workflow phase editing and run-phase visualization, plus interface
  updates and fixes. Engine and Web add candidate artifact checks and diagnosis
  judging using published workflow definitions.
- Gateway adds ticket/review history harvesting and Jira history pagination.
  Attachment handling reports partial failures and skipped files more clearly.
- Agents is repinned to the promoted Preview build. Its changes since 0.2.4 are
  CI image-tag isolation; there are no Agent application-code changes.

## Required database ordering

The installer runs a database-only job from the incoming Web image while the
old Web servers/workers remain deployed. It migrates Web's schema and runs the
insert-only workflow definition bootstrap, then upgrades Engine and imports the
legacy catalog before replacing Web. Engine, Web and Gateway are not deployed
concurrently. No new values or secrets are required for an upgrade from 0.2.4.

The import is atomic and records completion once. Existing definition JSON is
preserved; missing defaults are inserted. Invalid legacy content stops import
without committing the completion marker. Resolve the named definition and retry;
do not delete customer definitions or reset the marker. Future definition
updates use the publication API, not runtime YAML files or repeated bootstrap.

Follow [UPGRADE.md](../../UPGRADE.md). Keep existing values, secrets, GCP VM
settings and Workload Identity bindings. Finish workflows and pause new starts
and definition-seeding jobs during the update. Rollback requires old Web before
old Engine and has limits for newly published app definitions; see
[rollback requirements](../rollback.md#rolling-back-from-025).

## Validation

The configured AWS simulation render passed schema validation for all 65
resources. The 46 existing repository tests passed. Customer read-only ECR
credentials could read all six updated image manifests and obtain every layer's
download URL. No application images were rebuilt or repackaged.

The existing AWS EKS `phoenix-byoc` installation was upgraded from the 0.2.4
application set to 0.2.5-rc.1, with the exact images and chart content pinned in
this release. Final stabilization changes release metadata only. The installer
and `verify.sh` passed; all nine Deployments were available. Existing user,
Enterprise, App, Ticket and workflow-run counts, PVC identities and credential
values were preserved. Web schema migrations increased from 160 to 162.

All 27 existing legacy definition JSON records remained unchanged. Bootstrap
added one missing default and Engine imported all 28 definitions with one
completion marker. The database-only bootstrap completed before Engine; all
Engine processes upgraded while Web still used the previous image.

One workflow in the existing test application was published through the new
Engine API and executed successfully using the existing Web-published Agent
bundle. It returned the expected report and non-root/FUSE evidence through the
Artifact API (run `01a18e64-ea95-7108-a940-c2193767caeb`). No temporary Engine
chart or filesystem-catalog overrides were needed.

The default-fixture render contained 66 resources: 63 validated and three skipped
for missing CRD schemas, with no errors. This is an upgrade and basic workflow
execution check, not acceptance of every UI or evaluation feature. Fresh-cluster
installation, sandbox scale-from-zero and customer GCP were not tested.
