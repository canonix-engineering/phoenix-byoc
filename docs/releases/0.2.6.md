# Phoenix BYOC 0.2.6 — incomplete candidate

This draft targets an upgrade from the published `v0.2.5` release. It is not
approved for installation or customer delivery. Web, frontend, Engine, OpenSandbox and Agent images are resolved and pinned.
Gateway remains on the published 0.2.5 pin because its intended Preview image
is absent and its CI is failing. Final compatibility is not yet qualified.

## Proposed changes

- Web adds application discovery and capability summaries, workflow brief
  updates, diagrams and a document reader, direct human-gate decisions, and
  dependency security fixes.
- Engine adds completed-run and snapshot retention, decouples artifact storage
  from the filesystem, improves missing-artifact responses, and handles lost
  external development-box leases.
- Agents adds CI tools, repository isolation and checkout recovery, reuses
  pinned bundles on resume, and improves publication and artifact acceptance.
  The selected Preview branch deliberately excludes the Pi migration.
- Gateway adds CI run inspection and retries, scoped repository reference and
  file reads, and expanded ticket and pull-request discussion retrieval.

## Upgrade risks requiring qualification

Engine enables workflow-run retention by default: terminal runs expire after
1,209,600 seconds (14 days), and the previous-snapshot retention limit is zero.
Cleanup can affect historical runs immediately after upgrade. Deleted data is
not restored by repinning old images. Review this policy before publication;
the existing BYOC values do not expose these new retention environment settings.

Web introduces six migrations: CI capability support; retention fields,
concurrent indexes and constraints; business-record foreign-key changes; and
dataset repository provenance. Engine validates the retention indexes. Preserve
the installer's incoming-Web database preparation before Engine deployment.
Customers managing migrations themselves must complete these migrations first.

The usage-account foreign key is removed and the pull-request foreign key now
nullifies the run reference on deletion. A schema rollback can fail after
retention removes referenced runs. Back up databases and artifact/snapshot data
according to the deployment's recovery policy before applying this candidate.

The installer must preserve existing customer values, credentials, PVCs, GCP VM
pool settings and Workload Identity bindings. Finish active workflows and pause
new starts during the upgrade. A rehearsal on AWS `phoenix-byoc` is recommended
because of the migrations and deletion behavior; none has been performed.

## Charts and validation

All seven application/infrastructure OCI charts were downloaded anonymously and
compared with frozen DevOps source `c519c153f8652a7046c18afe2fb6482963384b10`.
Five are identical. Gateway's change makes the existing startup threshold
configurable without changing its default. Engine's changes add optional
internal Testbox and volume/identity controls. These are not required by the
proposed customer update, so published chart pins are retained. Never overwrite
the existing chart versions with differing source content.

The 46 existing BYOC tests and 15 internal release-tool tests passed locally.
These tests do not prove runtime compatibility or migration success. Fixture rendering produced 66 resources: schema validation found 63 valid,
zero invalid/errors, and three skipped for unavailable CRD schemas. Eight
Preview Deployments and the Engine runtime Agent configuration passed live
readiness/digest checks. Customer image access, Gateway and the final combined
release still require qualification. See the candidate report and review
record under `.release/0.2.6/` for frozen source comparisons and blockers.

The Gateway Preview CI initially failed because Agents Preview had not yet
received the `cicd` category. The newer Agents promotion supplies it; failed
jobs were retried on the same Gateway commit. Attempt 2 passed the category check but failed image packaging because archived
Debian ca-certificates source `20250419~deb12u1` was missing in the pinned
DevOps packaging tool. Gateway CI remains a publication blocker; deployment
was skipped. The existing repair PR is Gateway #96; it now pins the merged Debian source
resolver workflow and still requires reviewer approval.

## Installation and rollback

blocked on retention policy, Gateway and final upgrade qualification.
