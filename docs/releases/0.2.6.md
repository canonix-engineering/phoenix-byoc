# Phoenix BYOC 0.2.6

This release supports an upgrade from published `v0.2.5`. Web, frontend,
Engine, OpenSandbox, Agents and Gateway are pinned to their selected Preview
commits. The AWS upgrade and installation verification passed.

## Changes

- Web adds application discovery and capability summaries, workflow brief
  updates, diagrams and a document reader, direct human-gate decisions, and
  dependency security fixes.
- Engine adds completed-run and snapshot retention, decouples artifact storage
  from the filesystem, improves missing-artifact responses, and handles lost
  external development-box leases.
- Agents adds CI tools, repository isolation and checkout recovery, reuses
  pinned bundles on resume, and improves publication and artifact acceptance.
  The selected Preview branch deliberately excludes the Pi migration.
- Gateway adds CI run inspection and retries, scoped repository reference and
  file reads, and expanded ticket and pull-request discussion retrieval.

## Upgrade behavior and recovery

Engine includes new completed-workflow retention. BYOC explicitly disables it
by default to preserve historical runs and snapshots during and after this
upgrade. Customers can opt in separately after choosing a retention policy.
The chart exposes the four settings; the Web identity receives the required
`workflow:retention:write` scope without changing credentials or restrictions.

Web introduces six migrations: CI capability support; retention fields,
concurrent indexes and constraints; business-record foreign-key changes; and
dataset repository provenance. Engine validates the retention indexes. Preserve
the installer's incoming-Web database preparation before Engine deployment.
Customers managing migrations themselves must complete these migrations first.

The usage-account foreign key is removed and the pull-request foreign key now
nullifies the run reference on deletion. A schema rollback can fail after
retention removes referenced runs. Back up databases and artifact/snapshot data
according to your recovery needs before upgrading.

The installer must preserve existing customer values, credentials, PVCs, GCP VM
pool settings and Workload Identity bindings. Finish active workflows and pause
new starts during the upgrade. The upgrade was rehearsed on AWS `phoenix-byoc` with retention disabled.

## Charts and validation

Engine chart 0.2.8 exposes the retention controls. BYOC sets cleanup to disabled
and preserves existing credentials and service identity restrictions. The other
chart pins remain unchanged. The Gateway chart source only adds an optional
startup-probe threshold with an unchanged default; that change is not required
by this delivery.

Application images are reused from CI. Gateway Preview includes the packaging
and catalog fixes from Gateway #96, promoted through #97. No local application
image builds are part of release preparation.

Static configuration checks cover disabled retention, explicit and derived
service identities, and preservation of tenant/application restrictions. The AWS upgrade applied all six Web migrations and preserved historical records,
PVC identities, configuration and secret values. See `UPGRADE.md` for installation
and recovery requirements. A workflow smoke check completed successfully with
a non-root FUSE workspace; an existing workflow artifact remained byte-for-byte
unchanged.
