## Changes from 0.2.1

- AgentFS workspaces, checkpoint capture/restore and recovery of missing workspace
  databases; FUSE allocation and permissions are scoped to exact Agent images.
- Recovery of interrupted sandbox resumes in Engine and Web.
- Agent-bundle publication is always enabled in the new applications. The
  dedicated publisher token and `agent-bundles` namespace must be available to
  Web, Artifact API and migration hooks.
- Ticket list and progress improvements, answers/retries from the list, pull
  request state/links, organization Value and Spend overview, and brief costs.
- Agent fixes for unknown model pricing, artifact paths in execution environments,
  required reports and distinguishing approved work from ticket resolution.
- Git LFS relay support and security updates in Gateway, frontend and Engine
  images. Application CI build/scan/sign jobs passed for the selected heads.

## Charts and upgrade inputs

- Web `0.2.3` → `0.2.4`: publisher namespace and token reach application boot
  and the database initialization hook.
- Engine `0.2.5` → `0.2.6`: publisher settings reach the pre-upgrade migration
  hook; OpenSandbox receives the current and retained Agent image allowlist.
- FUSE device-plugin `0.1.0`: public OCI chart, pinned plugin image, installed
  before application upgrades unless an existing provider is explicitly reused.
- Bundled PostgreSQL bootstrap `0.1.0` → `0.1.1`: publisher settings also reach
  the separate Rails schema job. The EKS rehearsal caught a missing namespace
  in this job before Engine could be upgraded; all three migration jobs now
  have regression coverage for these settings.
- Remaining chart and infrastructure image pins retain the 0.2.1 baseline.
  PostgreSQL and Valkey stay bundled; this is not a Redis-to-Valkey cutover.

Two Web migrations add optional overview budget/hourly-cost fields and allow the
`master-agent` toolbox kind. Existing users, credentials, tenant, provider settings,
storage and placement must be retained. The normal `--generate-secrets` flow
preserves populated secrets and adds missing internal fields.

## Qualification scope

Release qualification is performed in `phoenix-byoc` on AWS EKS. We do not test
in the customer's GCP environment or request access to it. The final delivery
includes instructions for the customer to apply the tested release themselves,
retaining their existing GCP settings. Cluster prerequisites are documented in
[AgentFS](../agentfs.md); the installer checks node capacity before upgrading Engine.

Before stable publication, complete the EKS upgrade from 0.2.1, verify data and
secret preservation, application readiness, bundle publication, a real workflow,
artifact download, human-input resume and AgentFS checkpoint recovery. Record the
results, then approve the stable version and publication. No functional upgrade
success is claimed by this preparation record.

See [the upgrade procedure](../../UPGRADE.md). The client chat message is prepared
outside the repository after qualification.
