# Phoenix BYOC 0.2.3

Application update from 0.2.2, frozen from Preview on 2026-10-27. Channel: stable.
Existing charts, infrastructure images, customer values and secrets are retained.

## Changes

- Web imports tickets through the app's assigned ticket integration, with clear
  guidance when none is assigned. Updates net-ssh from 7.3.2 to 7.3.8.
- Engine preserves the acknowledged suspension retention deadline when resuming
  a workflow, instead of rejecting or shortening it when the active idle TTL is
  shorter. It does not reopen terminal attempts or rewrite existing records.
- Agents use a script-based PR publisher with retained publication receipts and
  retry reconciliation, and complete verified no-change deliveries without
  creating an unnecessary PR. Workflow output corrections preserve completed
  work. Repository checks use Sonnet instead of Haiku.
- Existing workflows keep their previously pinned Agent image and bundle; new
  workflows use the new Agent behavior.

## Chart and upgrade review

All chart versions remain identical to 0.2.2. Web and Engine add no database
schema migrations, required environment variables or deployment dependencies.
The new publisher executable and host adapter ship together in the Agent image.

DevOps main adds `SANDBOX_RESOURCE_CLASSES_JSON`, optional `DEV_BOX_SECRETS_KEY`
and expanded default sandbox size presets to its Engine chart source without
changing chart version 0.2.6. The selected Engine source does not consume those
new variables. This release retains the already-published immutable 0.2.6 chart;
it does not republish that version or adopt unrelated resource-size defaults.
No customer values or secret changes are required for this update.

## Validation scope

Application CI, Preview deployment completion, live Preview image/readiness
checks, customer image access and static release rendering were checked.
A separate installation/upgrade in `phoenix-byoc` was intentionally not run.
No customer GCP deployment or test was performed. The prior 0.2.2 upgrade result
must not be treated as an upgrade test of these new application images.

Agent developer evidence includes targeted publisher, retry, no-change and
output-correction checks. Its publisher verification notes also record timing
failures in a full-suite attempt and no deployed end-to-end publisher/Windows VM
acceptance. Green CI covers its configured jobs, not every application scenario.
Suspension resume and scale-from-zero behavior were not revalidated for this
release. These limits do not introduce schema, storage or installer changes.

Follow [the upgrade instructions](../../UPGRADE.md), retaining the existing
namespace and configuration. Backups are optional for the procedure.
